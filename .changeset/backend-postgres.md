`postgres({ blob })` from `@vercel/board/backend-postgres` keeps a board on Postgres (`npm i pg`): its log and its tables in one database, shared by every instance that serves it, and its files in the blob store it requires, so a board you host runs on serverless functions. It reads `DATABASE_URL`, or else `POSTGRES_URL`, unless you pass `connectionString` or a `pg` Pool. Apply `node_modules/@vercel/board/sql/postgres/schema.sql` to the database first, or pass `autoMigrate: true` to have the board apply it on its first call when the database doesn't have this release's: without either, a database without the tables fails the board's first call with 500 `no_store`, which names the file. `backend.tables()` and `backend.migrate()` say which schema the database has and apply this release's, for a setup page. `vercelBlob()` from `@vercel/board/backend-postgres/blob-vercel` (`npm i @vercel/blob`) is a private Vercel Blob store that takes files up to 100 MB, and `fsBlob(dir)` and `memoryBlob()` are for development and tests. Its timers run in the process, or on Vercel Queues with `vercelQueues()` from `@vercel/board/backend-postgres/scheduler-vercel` and the backend's `scheduler` mounted in a route of its own. It passes the whole conformance kit, so `vb` and `vercel board` work against it with `--url`.
